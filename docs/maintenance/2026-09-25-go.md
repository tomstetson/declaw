# Go documentation helper maintenance — 2026-09-25

The separate `scripts/docs-i18n` module now uses Goldmark 1.7.17 and
`golang.org/x/net` 0.56.0. Its minimum Go version is 1.26.8 so automatic toolchain
selection cannot retain the older unsupported 1.24 compiler. Verification used
Go 1.27.1. The Node gateway and Python tools do not depend on this module.

The earlier graph contained versions listed in the [Goldmark HTML-renderer
advisory](https://pkg.go.dev/vuln/GO-2026-5320) and [x/net HTML-parser
advisories](https://pkg.go.dev/vuln/GO-2026-5028). Source analysis found no call to
the affected renderer or full-tree HTML parser: this helper parses Markdown
source spans and uses the HTML tokenizer. The original symbol scan had no
reachable vulnerable function. This is dependency hygiene, not a claim that an
exploitable gateway flaw was reproduced or that the translator sanitizes HTML.

Fresh `govulncheck -json ./...` has no findings at module, package or symbol
level. With dependencies already fetched, these checks pass without model calls
or network fetching:

```sh
cd scripts/docs-i18n
GOTOOLCHAIN=local GOPROXY=off GOSUMDB=off go test -mod=readonly ./...
GOTOOLCHAIN=local GOPROXY=off GOSUMDB=off go vet -mod=readonly ./...
GOTOOLCHAIN=local GOPROXY=off GOSUMDB=off go run -mod=readonly . -h
```

There are no existing Go tests, so `go test` above verifies compilation only.
No document translation, paid model call or external-provider integration was
run. The resolved graph and application source are otherwise unchanged.

Rollback is a focused revert of `go.mod` and `go.sum`, followed by compilation
with the retained patched compiler. That restores flagged dependency versions;
keep the patched graph available until any rollback is verified.
