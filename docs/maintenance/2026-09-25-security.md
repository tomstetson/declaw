## Pi security backport

The application depends on the Pi 0.55 API. Upgrading that API wholesale breaks this fork, so the four affected implementation files receive a checked-in, hash-bound backport of upstream security changes:

- Private extension download/cache directories and containment checks for every Git install scope; raw, percent-encoded and Windows traversal forms are rejected (GHSA-jfgx-wxx8-mp94).
- Auth files receive owner-only permissions at creation, before credential bytes are written (GHSA-r95r-rj6r-c39x).
- Exported HTML restricts link schemes and escapes attributes, including quoted payloads, in both Pi and DeClaw's renderer (GHSA-7v5m-pr3q-6453).

Upstream references: [private cache](https://github.com/earendil-works/pi/commit/ea3465a8e371a12d0167a06b60f93878e3a3df44), [Git containment](https://github.com/earendil-works/pi/commit/a98e087e5d08ea2a536bf73dbb0aebb87c3ef72e), [auth creation](https://github.com/earendil-works/pi/commit/135fb545f99106a4a249274f129b90bc0a77d347), and [HTML links](https://github.com/earendil-works/pi/commit/6cb23f9b5d5b6d1747672f535b167d0d809ac010).

pnpm applies the checked-in patch. npm installations run `scripts/apply-pi-security.mjs`, which accepts only the exact 0.55.0 upstream or already-patched file hashes, validates all inputs before writing, and fails on unknown content. The published file list includes the installer, patched files, manifest and upstream MIT license. Installations that disable lifecycle scripts must explicitly run this installer before use. The prepare step now preserves an existing Git hooks configuration, including global security hooks.

## Linux audit test fixture

The remaining full-suite stall came from the audit error-path test choosing
`/proc/nonexistent/audit.jsonl`. On Linux Node 22, recursive directory creation
under that virtual filesystem can loop synchronously instead of returning an
error, preventing the test timeout from firing. A separate four-second child
process reproduced the hang; a regular-file parent returned ENOTDIR in 32 ms.

The test now uses a real temporary file as the parent of the audit path, retaining
the best-effort logging assertion and checking that the file's bytes are
unchanged. All 19 audit tests pass with this portable failure fixture. Production
logging behavior and the full CI test inventory are unchanged.
